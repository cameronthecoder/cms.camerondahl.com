This is the content backend for camerondahl.com. You write and publish here; the website is a separate app that fetches published content from this server's API and renders it. Nothing on this server is the public site. The values on this page are read from the running configuration, so they show how this server is set up.

The big picture

  1. Author here. Pages, posts and snippets are edited in this Wagtail admin and stored in the database.
  2. Publish. Only published (“live”) content is visible to the outside world. Drafts and unpublished changes stay private.
  3. The website fetches it. camerondahl.com calls {{ api_root }} and renders what it gets back. Images and files are served from this server; the API returns full URLs to them.

So a change you publish appears on the site as soon as the frontend next fetches it. How quickly that happens depends on the frontend's caching, not on anything here.

Where content lives

Content is either a page (in the page tree, with drafts, revisions and scheduling) or a snippet (a reusable record, no tree).

Pages

  • Home is the root. It can hold exactly the two pages below.
  • Blog index (only one allowed) holds every post. Posts are added as its children.
  • Blog post: a writing. Title, intro, header image, author, categories, tags, the body, and an optional list of references (citations).
  • About (only one allowed): the biography.{% if links.about %} Edit it.{% endif %}

Writing a post

A post's body is a list of blocks, added in any order:

  • Text: rich text, with a size option.
  • Image: pick an image, then either write alt text or tick “decorative” (one is required), plus an optional caption. Resized copies (640, 1280 and 1920 px wide, never enlarged) are generated automatically so the site can serve the right size for each screen.
  • Code: choose a language and type into the code editor (line numbers, syntax colouring, auto-indent). Tab indents; press Esc then Tab to move on to the next field. When the post is saved, the code is turned into coloured HTML for the site using the {{ code_theme }} theme{% if links.code_theme %} (change it; changing it re-colours every existing post){% endif %}. The editor's colours are only for editing and don't affect the site.
  • Quote: the quoted text, plus optional attribution and a link to the source.
  • Video and Document (a file from the document library).

Reading time is worked out automatically from the text blocks, at about 200 words per minute.

Publishing and previews

  • Save draft keeps changes private. Publish makes them live, so they appear in the API and on the site.
  • Every save is kept as a revision; you can compare or roll back from the page's history.
  • Preview shows the draft in the real site design. The admin creates a short-lived signed token and loads {{ preview_client_url }} with it; the site then fetches the draft from {{ api_root }}preview/. The token is the only key, so a preview link works without signing in but stops working when it expires.

If previews come up blank, the site at that address has to handle the preview query on its home page and allow being shown inside this admin.

Deploying changes

The server is a DigitalOcean droplet. The app runs under gunicorn behind nginx, with its configuration in a .env file in the project folder. After pulling new code:

source venv/bin/activate
pip install -r requirements.txt     # if dependencies changed
python manage.py migrate            # apply database changes
python manage.py collectstatic      # copy admin CSS/JS into place
# then restart gunicorn
Always restart gunicorn after migrating. Until it restarts, it keeps running the old code against the new database. When block types change, that breaks pages with errors such as “… value must be an integer.”

The code editor is a pre-built JavaScript file that's checked in, so deploys don't need Node. It only needs rebuilding when the editor itself changes: npm install && npm run build in blog/static_src/code-editor/, then commit the result.
